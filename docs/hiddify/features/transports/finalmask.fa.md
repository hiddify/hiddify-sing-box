# finalmask

[English](finalmask.en.md) · [همهٔ قابلیت‌های هیدیفای](../../index.fa.md)

`finalmask` ماسک‌های finalmask در Xray-core را روی اتصال‌هایی که یک خروجی باز می‌کند اعمال می‌کند.
ماسک بایت‌های روی سیم را تغییر می‌دهد: آن‌ها را تکه‌تکه می‌کند، بستهٔ نویز اضافه می‌کند، هدر می‌افزاید یا
آن‌ها را در پروتکلی دیگر (DNS، ICMP، جریانی شبیه Minecraft و…) می‌پیچد. این فیلد `finalmask` در
فیلدهای اتصال (dial) است؛ پس روی هر خروجی که اتصال می‌سازد (و روی سرورهای DNS و جاهای دیگری که
فیلدهای اتصال را می‌پذیرند) قابل تنظیم است. JSON آن همان `streamSettings.finalmask` در Xray است.

## چرا از آن استفاده کنیم

- برای استفاده از سرور Xray که با ماسک‌های finalmask راه‌اندازی شده است: کلاینت باید همان ماسک‌ها را
  اعمال کند، وگرنه سرور ترافیک را نمی‌فهمد.
- برای تغییر شکل اتصال روی سیم بدون تغییر پروتکل: تکه‌تکه کردن ClientHello در TLS (`fragment`)،
  فرستادن بسته‌های UDP بی‌معنا پیش از دست‌دهی WireGuard یا QUIC (`noise`)، یا مبهم‌سازی UDP با رمز
  (`salamander`).

## چطور از فیلترینگ عبور می‌کند

فیلترها روی اولین بایت‌ها و بسته‌های اتصال، اندازه و زمان‌بندی آن‌ها تطبیق می‌دهند و ماسک‌ها دقیقاً همین را
تغییر می‌دهند. `fragment` ClientHello را به تکه‌های کوچک می‌برد تا فیلتری که آن‌ها را سرهم نمی‌کند
نتواند SNI را بخواند. `noise` اول بسته‌های تصادفی می‌فرستد تا جریان با دست‌دهی واقعی شروع نشود.
ماسک‌های هدر و پوششی ترافیک را شبیه پروتکلی دیگر، یا شبیه بایت‌های تصادفی، می‌کنند.

ماسک‌هایی که فقط اندازه و زمان را تغییر می‌دهند (`fragment`، `noise`) با هر سروری کار می‌کنند.
ماسک‌هایی که محتوا را تغییر می‌دهند (هدرها، `salamander`، `sudoku`، `xdns`، `xicmp`، `xmc`،
`mkcp-legacy`، `realm`) همان ماسک را روی سرور لازم دارند، یعنی سرور Xray که برای آن تنظیم شده باشد.
وقتی فیلتر IP سرور را مسدود کرده باشد، ماسک کمکی نمی‌کند.

## چطور کار می‌کند

- ماسک‌های `tcp` هر اتصال TCP خروجی را می‌پوشانند و ماسک‌های `udp` هر سوکت UDP و اتصال UDP متصل را.
- ماسک‌ها به ترتیب فهرست اجرا می‌شوند: اولین ماسک بایت‌هایی را که خروجی می‌نویسد می‌گیرد و خروجی آخرین
  ماسک روی سیم می‌رود. پاسخ‌ها به ترتیب برعکس از آن‌ها می‌گذرند.
- ماسک‌ها زیر پروتکل و لایهٔ TLS آن قرار دارند، پس دقیقاً همان چیزی را می‌بینند که روی سیم می‌رود. با
  `detour`، اتصالی را می‌پوشانند که از طریق خروجی detour ساخته شده است.
- فقط سمت کلاینت پیاده شده است: ورودی‌ها `finalmask` نمی‌گیرند.
- ماسک‌ها همان کد Xray-core هستند (منتقل‌شده از Xray-core v26.7.28)؛ پس رفتار و تنظیمات آن‌ها از
  مستندات `finalmask` در Xray پیروی می‌کند.

## پیکربندی

یک خروجی VLESS که ClientHello آن تکه‌تکه می‌شود، و یک endpoint از نوع WireGuard که پیش از هر دست‌دهی
نویز می‌فرستد:

```json
{
  "outbounds": [
    {
      "type": "vless",
      "server": "example.com",
      "server_port": 443,
      "uuid": "bf000d23-0752-40b4-affe-68f7707a9661",
      "tls": { "enabled": true, "server_name": "example.com" },
      "finalmask": {
        "tcp": [
          { "type": "fragment", "settings": { "packets": "tlshello", "length": "100-200", "delay": "10-20" } }
        ]
      }
    }
  ],
  "endpoints": [
    {
      "type": "wireguard",
      "tag": "wg",
      "address": ["10.0.0.2/32"],
      "private_key": "...",
      "peers": [{ "address": "203.0.113.1", "port": 51820, "public_key": "...", "allowed_ips": ["0.0.0.0/0"] }],
      "finalmask": {
        "udp": [
          { "type": "noise", "settings": { "noise": [{ "rand": "10-50", "delay": "5-10" }] } }
        ]
      }
    }
  ]
}
```

| فیلد | نوع | پیش‌فرض | معنا |
|---|---|---|---|
| `finalmask.tcp` | array | — | ماسک‌های اتصال‌های TCP، به ترتیب. |
| `finalmask.udp` | array | — | ماسک‌های UDP، به ترتیب. |
| `finalmask.quicParams` | object | — | پذیرفته می‌شود تا کانفیگ‌های Xray بارگذاری شوند؛ استفاده نمی‌شود. پروتکل‌های QUIC در sing-box گزینه‌های خودشان را دارند. |
| `…[].type` | string | — | نوع ماسک (پایین را ببینید). حروف کوچک و بزرگ فرقی ندارد. |
| `…[].settings` | object | `{}` | تنظیمات ماسک، دقیقاً مثل Xray. |

نوع‌های پشتیبانی‌شده:

| نوع | `tcp` | `udp` | کار | تنظیمات اصلی |
|---|---|---|---|---|
| `fragment` | بله | — | اولین نوشتن‌ها (یا ClientHello در TLS) را با تأخیر به تکه‌های کوچک می‌برد. | پایین را ببینید |
| `header-custom` | بله | بله | بایت‌های دلخواهی که سرور انتظار دارد (هدر پروتکل جعلی) اضافه می‌کند. | TCP: `clients`، `servers`، `errors`؛ UDP: `mode`، `client`، `server` |
| `sudoku` | بله | بله | مبهم‌سازی Sudoku با کلید رمز. | `password`، `ascii`، `customTable`، `customTables`، `paddingMin`، `paddingMax` |
| `xmc` | بله | — | جریان را شبیه اتصال Minecraft می‌کند. | `hostname`، `profiles`، `password` |
| `noise` | — | بله | پیش از بسته‌های واقعی، بسته‌های تصادفی یا ثابت می‌فرستد. | `noise` (فهرستی از `rand`، `randRange`، `type`، `packet`، `delay`)، `reset` |
| `salamander` | — | بله | مبهم‌سازی Salamander در Hysteria2؛ با `packetSize` گونهٔ Gecko که اندازهٔ بسته‌ها را هم تغییر می‌دهد. | `password`، `packetSize` (حداکثر ۲۰۴۸) |
| `mkcp-legacy` | — | بله | هدرهای قدیمی بسته‌های mKCP (`dns`، `dtls`، `srtp`، `utp`، `wechat`، `wireguard`) یا لایهٔ AES-GCM آن. | `header`، `value` |
| `xdns` | — | بله | UDP را در درخواست‌های DNS حمل می‌کند. | `resolvers` (کلاینت، هر کدام با `+udp://`) |
| `xicmp` | — | بله | UDP را در بسته‌های ICMP echo حمل می‌کند. | `ips`، `dgram` |
| `realm` | — | بله | از راه NAT hole punching با سرورهای STUN و یک نشانی rendezvous به طرف مقابل وصل می‌شود. | `url` (`realm://` یا `realm+http://`)، `stunServers`، `tlsConfig` |

نوع ناشناخته، نوعی که فقط TCP است در `udp` (یا برعکس)، یا تنظیمات نادرست، خطای پیکربندی می‌دهد که
نام ماسک را می‌گوید، مثل `finalmask.tcp[0] fragment`.

تنظیمات `fragment`:

| فیلد | نوع | پیش‌فرض | معنا |
|---|---|---|---|
| `packets` | string | — | `tlshello` ClientHello را در TLS تکه می‌کند؛ بازه‌ای مثل `"1-3"` همان نوشتن‌های اتصال را تکه می‌کند. |
| `length` | range | — | اندازهٔ هر تکه به بایت. |
| `delay` | range | `0` | مکث میان تکه‌ها به میلی‌ثانیه. |
| `lengths` | range list | — | یک طول برای هر تکه، به جای `length`. |
| `delays` | range list | — | یک تأخیر برای هر تکه، به جای `delay`. |
| `maxSplit` | range | — | بیشترین تعداد تکه‌ها. |

بازه به شکل `"from-to"` یا یک عدد است؛ فهرست بازه آرایه‌ای از آن‌ها، یا تنها یکی است.

گزینه‌های مرتبط: [`tls_fragment`](../tls-fragment.fa.md) خروجی به‌عنوان اولین ماسک `fragment` اضافه
می‌شود. [`tls_tricks`](../tls-tricks.fa.md) خود ClientHello را تغییر می‌دهد و ماسک نیست.
`tls_fragment` را نمی‌توان با `tcp_fast_open` به کار برد.
