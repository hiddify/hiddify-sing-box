# IPv6 بر اساس خروجی

[English](ipv6-by-outbound.en.md) · [همهٔ قابلیت‌های هیدیفای](../../index.fa.md)

نشانی IPv6 را فقط جایی به کلاینت می‌دهد که به جایی برسد. پایش برای هر خروجی یاد می‌گیرد که آیا
IPv6 را رد می‌کند یا نه (`ipv6_probe` در `experimental.monitoring`)؛ سپس قاعدهٔ DNS با
`ipv6_by_outbound` تا وقتی خروجی‌ای که ترافیک از آن می‌گذرد IPv6 ندارد، پرسش‌های AAAA را
بی‌پاسخ می‌گذارد، و قاعدهٔ مسیریابی با `ipv6_unavailable_via` اتصال‌های IPv6ای را که باز هم
می‌آیند رد می‌کند تا کلاینت بی‌درنگ به IPv4 برگردد.

## چرا از آن استفاده کنیم

- گوگل، یوتیوب و بیشتر سایت‌های بزرگ IPv6-اول هستند: مرورگری که پاسخ AAAA بگیرد با IPv6 وصل
  می‌شود. از پراکسی‌ای که IPv6 ندارد، پراکسی اتصال را می‌پذیرد و بعد می‌بندد، که کروم آن را
  «unexpectedly closed the connection» (`ERR_CONNECTION_CLOSED`) نشان می‌دهد و هرگز با IPv4
  دوباره تلاش نمی‌کند، در حالی که اپ‌های IPv4 کار می‌کنند. با این قابلیت، چنین مرورگری فقط
  نشانی IPv4 می‌گیرد و سروری که واقعاً IPv6 دارد همچنان IPv6 می‌دهد.
- TUN مسیر IPv6 خود را نگه می‌دارد، پس هیچ چیز بیرون از VPN از دستگاه خارج نمی‌شود، و سروری که
  فقط نشانی IPv6 دارد همچنان مسیر می‌شود: هیچ خانواده‌ای یکسره رد نمی‌شود.

## چطور از فیلترینگ عبور می‌کند

عبور نمی‌دهد؛ نمی‌گذارد پراکسی سالم خراب به نظر برسد.

## چطور کار می‌کند

- هر خروجی و endpoint جداگانه آزموده می‌شود: پس از آنکه به تست URL پاسخ داد، پایش یک اتصال
  TCP از طریق آن به `ipv6_probe` (به‌طور پیش‌فرض `[2606:4700:4700::1111]:443`) با مهلت ۳ ثانیه
  باز می‌کند، می‌بندد و برای همان خروجی ثبت می‌کند که آیا رسید یا نه. پس یک پراکسی می‌تواند
  IPv6 داشته باشد و پراکسی بعدی نه. هر خروجی یک بار در هر اجرا آزموده می‌شود، و یک بار دیگر
  وقتی نتیجه‌اش از کش خوانده شده؛ نتیجه همراه نتایج تست URL همان خروجی ذخیره می‌شود.
- گروه برای عضوی که انتخاب کرده پاسخ می‌دهد، پس پاسخ با انتخاب عوض می‌شود.
- `ipv6_by_outbound` روی قاعدهٔ DNS: تا وقتی معلوم است خروجی نام‌برده IPv6 ندارد، پرسش با
  استراتژی `ipv4_only` اجرا می‌شود (AAAA پاسخ خالی می‌گیرد)؛ وگرنه استراتژی خود قاعده اعمال
  می‌شود. خروجی‌ای که هنوز آزموده نشده چیزی را عوض نمی‌کند.
- `ipv6_unavailable_via` روی قاعدهٔ مسیریابی: با اتصالی به نشانی IPv6 منطبق می‌شود، تا وقتی
  معلوم است خروجی نام‌برده IPv6 ندارد. با `"action": "reject"` کلاینت reset می‌گیرد و IPv4 را
  امتحان می‌کند؛ هرگز با مقصد IPv4، با خروجی‌ای که IPv6 دارد، یا با خروجی آزموده‌نشده منطبق
  نمی‌شود.

## پیکربندی

```json
{
  "dns": {
    "rules": [
      { "action": "route", "server": "remote", "strategy": "prefer_ipv4", "ipv6_by_outbound": "select" }
    ]
  },
  "route": {
    "rules": [
      { "ip_version": 6, "ipv6_unavailable_via": "select", "action": "reject" }
    ]
  },
  "experimental": {
    "monitoring": { "ipv6_probe": "[2606:4700:4700::1111]:443" }
  }
}
```

| فیلد | کجا | نوع | پیش‌فرض | معنی |
|---|---|---|---|---|
| `ipv6_by_outbound` | اکشن قاعدهٔ DNS ‏`route`، `route_options` | string | | یک خروجی یا گروه؛ تا وقتی IPv6 ندارد، پرسش‌های AAAA پاسخ خالی می‌گیرند. |
| `ipv6_unavailable_via` | قاعدهٔ مسیریابی | string | | یک خروجی یا گروه؛ قاعده با مقصد IPv6 منطبق می‌شود تا وقتی آن خروجی IPv6 ندارد. |
| `ipv6_probe` | `experimental.monitoring` | string | `[2606:4700:4700::1111]:443` | نشانی و پورت IPv6 که آزمون به آن وصل می‌شود. `none` آزمون را خاموش می‌کند: چیزی دانسته نمی‌شود و دو فیلد قاعده کاری نمی‌کنند. |

## نکته‌ها

- کانفیگ‌های خود هیدیفای هر دو قاعده را روی selector اصلی می‌گذارند، پس رفتار با پراکسی‌ای که
  کاربر انتخاب کرده عوض می‌شود.
- آزمون یک اتصال برای هر خروجی در هر اجراست؛ از طریق پراکسی، یک اتصال بیشتر است که سرور
  می‌بیند، به resolver کلادفلر.
